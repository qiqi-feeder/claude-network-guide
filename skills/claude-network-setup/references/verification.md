# 验收与回滚

先备份，再对候选文件做内核校验；逐步接管，避免先切断唯一管理通道。每次改变网络关键行为后做相关验证，不无意义重复全套测试。

## 验收矩阵

| 项目 | 验证方法 | 不能据此声称 |
|---|---|---|
| 节点出口 | 独立节点 HTTPS 请求，必要时两个检测源 | 账号必然可用或 IP 永久干净 |
| Claude 路由 | 真实 TLS 连接，查看内核连接链与命中规则 | 仅看到配置文字就已生效 |
| 国内网站 | 抽样访问并核对 DIRECT | 所有国内服务均兼容 |
| DNS | 系统查询、内核 DNS 路径与浏览器 DNS 检测相互核对 | DNS 出口必须等于 VPS IP |
| UDP/WebRTC | 实际浏览器 STUN，核对显示地址 | 有候选 IP 就是真实 IP 泄漏 |
| IPv6 | 双栈路由、AAAA/Fake AAAA 实际连接链 | 顶层 false 就不会绕行 |
| 故障 | 临时仅让自建节点不可用，请求新建连接 | 退出 Clash 后也一定阻断 |
| 国内兼容 | 用户重试微信图片、文件、常用业务 | 检测分数正常就没有业务问题 |
| 持久化 | 重启客户端，复查 profile 与实际路径 | 仅保存文件即跨重启有效 |

可用 https://ip.net.coffee/claude/ 和其他独立检测页。评分是第三方结果；正常 HTTP 响应、TLS、网页登录成功分开记录。不要提交用户账号或接受条款来“顺便验证”。

## 故障测试的安全顺序

保存正在运行的完整配置和选择状态；候选测试副本中只修改自建节点端口为不可用值。验证候选后临时加载，发起新的受保护 IPv4 和 IPv6 连接。预期均失败，不出现 DIRECT。务必用 try/finally 恢复，即使测试抛异常也恢复；恢复后复测并停止临时进程。

不要把整组切为 DIRECT 来模拟故障；不要修改服务器公网防火墙破坏唯一 SSH 通道。内核进程仍开着的失败测试不能代表客户端退出、休眠或开机间隙安全。

## 交付报告

脱敏记录版本、来源日期/哈希、配置入口、实际修改、每项结果、未测项、用户确认的国内业务和回滚位置。截图可能含公网地址、邮箱和历史记录，默认留私密本地，发布必须脱敏。

回滚先恢复原源配置与偏好，再重启客户端并验证网络；不能只恢复生成文件。用户仍需旧服务器服务时，不顺便卸载。更新失败保留上一可用配置，不将空规则集投入运行。
